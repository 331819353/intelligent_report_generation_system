# 智能问数 v1.5 资产中心与问答工作台升级基线

状态：`IMPLEMENTING`

目标依据：`智能问数项目技术架构与实施方案 v1.5`（2026-08-04）

本轮只把附件作为目标架构，把当前项目作为升级对象。现有指标、数据集、只读执行、
语义发布、NebulaGraph、SQL Guard 和评测证据等已验证能力继续复用；旧页面的信息架构、
重复技术概念和与 v1.5 冲突的浏览器侧拼装逻辑不再保留。

## 1. 审计结论

### 1.1 可以保留的运行时能力

- 活动 `semantic_version/content_hash`、不可变发布包与四类投影状态；
- 指标、维度、成员、数据集、关系、策略和质量对象的发布清单；
- NebulaGraph 关系裁决、只读参数化执行、SQL Guard、结果验证和 AccuracyEvidence；
- `/api/v1/questions`、NDJSON 进度流、澄清续跑、取消和结构化反馈；
- 原生指标与维度编辑器，作为统一资产中心的类型化深层编辑入口。

### 1.2 必须替换的旧实现

| 旧实现 | v1.5 冲突 | 本轮处理 |
| --- | --- | --- |
| “指标与维度 / 业务词汇 / 维值决策图 / 解析规则”五个并列页签 | 把业务资产、技术投影和运行记录混为一级资产 | 删除旧页签，重搭五类运行时资产目录 |
| 资产概览只统计四种原生对象 | 不能表达发布包中的 Domain、Entity、Time、Relation、Policy、DQ 等类型 | 目录直接读取活动发布清单并按 v1.5 分类 |
| 向量和维值决策图作为用户资产入口 | 向量与 NebulaGraph 点边应是可重建投影 | 降为“理解增强/发布治理”中的只读投影状态与诊断入口 |
| 资产列表缺少统一信封 | 无法统一展示稳定 ID、版本、Owner、生效期、敏感级别和运行资格 | 增加统一发布资产读模型 |
| 问答结果只渲染表格 | 已返回的确定性图表规范未被消费 | 增加 KPI、图表、表格的确定性渲染 |
| 黄金评测控制面长期占用问答右栏 | 终端用户结果页应优先展示口径、来源、新鲜度和证据 | 评测入口移入资产治理；问答右栏改为答案证据抽屉 |
| 候选/Tool 细节默认展开 | 运行时不应把诊断记录当作业务结果 | 默认仅显示公开验证阶段，完整轨迹进入授权诊断区 |

## 2. 目标页面合同

### 2.1 资产管理中心

一级目录固定为：

1. 业务语义资产；
2. 查询语义资产；
3. 理解增强资产；
4. 治理保障资产；
5. 系统运行配置。

资产中心同时提供总览，但总览不是第六类资产。列表公共字段固定为：名称、稳定 ID、
类型、主题域、认证/发布状态、对象版本、Owner、敏感级别、运行资格、依赖/投影状态和
最后更新时间。发布清单中的类型化 `contract` 只作为详情读取来源，浏览器不允许用自由
JSON 修改线上对象。

活动发布中的对象按下列规则归类：

- 业务语义：Domain、BusinessTerm、Entity、SemanticModel、Measure、Metric、
  Dimension、DimensionValue、Time、Cohort；
- 查询语义：SemanticModel、Relation、Dataset、TableColumn；
- 理解增强：BusinessTerm、DimensionValue、CertifiedExample、ParsingRule；
- 治理保障：Policy、QualityRule，以及发布、投影和评测门禁；
- 系统运行配置：当前 Tool、模型/路由/预算/SQL/展示策略的可见版本和健康状态；敏感参数
  不下发普通页面。

### 2.2 智能问答

结果页按固定顺序展示：

```text
问题原文
-> 口径确认条（指标 / 分组 / 筛选 / 时间 / 人群 / 粒度）
-> 结论与 KPI
-> 确定性图表 / 表格
-> 数据截止时间 / 来源 / 可信等级 / trace
-> 证据抽屉（定义、维度值归属、血缘、验证、技术信息）
-> 结构化反馈
```

前端只渲染后端已返回的结构化结果和图表建议，不计算新业务数字。无数据、数据未刷新、
无权限、需要澄清和系统失败必须保持不同状态。

## 3. 分阶段提交与退出门槛

### 阶段 A：统一发布资产读模型与资产中心重搭

- 后端提供按活动发布读取的统一资产目录、类型统计和详情；
- 前端删除旧资产一级页签，使用五类目录和统一资产信封；
- 既有类型化编辑器保留为深层入口，投影只读展示；
- 单元、API 契约、React lint/build 通过后提交并推送 `master`。

### 阶段 B：问答结果与证据体验升级

- 消费 `answer.chart/resultSets/asOf`、执行证据和运行时版本；
- 增加 KPI/图表/表格、口径条、新鲜度/来源、证据抽屉和状态区分；
- 保留现有进度结论改动，不覆盖工作区中已存在的超时与分组维度修复；
- React lint/build 与问答前端回归通过后提交并推送 `master`。

### 阶段 C：端到端验证与冲突清理

- 删除不再被路由引用的旧资产页签和旧页面入口；
- 执行 Go 全量测试、React lint/build、仓库 CI；
- 在可用本地环境中验证登录、资产目录、问答、澄清、结果和证据交互；
- 独立提交并推送 `master`。

## 4. 准确率边界

页面升级和工程测试不能替代 v1.5 要求的 2,000+ 双人复核 sealed test。仓库应继续以
“点估计不低于 96% 且 95% Wilson 下界不低于 95%”作为发布门禁；真实样本不足时必须
明确阻断，不能用点赞率、SQL 可执行率或演示夹具宣称已经达到 95%。
