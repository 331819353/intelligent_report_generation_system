# 智能报告生成（LLM 自主生成报告）开发设计

> 状态：设计稿 v1（2026-08-18），对应 docs/13 的 G1–G12。原则：在现有 Report bounded context 内**增量**演进，
> 不引入第二套渲染器 / 运行时 / 发布链；所有新能力在无模型提供方时确定性可用（docs/06 §4 规则 17）。
> 现有基线：`internal/report/{model.go,operation,compiler,http,runtime,publication,template,insight,reportinsight,reportai}`，
> `web/src/report/{designer,render,runtime,api,templates}`；迁移编号已用至 `000361`，本文新迁移从 `000362` 起。

## 1. 架构总览

```
                 ┌──────────────── 生成编排 reportgen（新）────────────────┐
意图/模板/参数 ─►│ ContextPack ─► Blueprint(LLM) ─► Validate ─► Expand ─►  │
                 │ LayoutSolve ─► DraftExecute ─► Refine(LLM,可选) ─►       │
                 │ Narratives(批量 derive/generate/verify) ─► Summary ─►    │
                 └───────────────────────────┬─────────────────────────────┘
                                             ▼
                          Report Definition 1.1（受控 Operation 落草稿）
                                             ▼
                 现有：compiler.Normalize/Validate → runtime(Session/ExecutionTarget) → publish
                                             ▲
   新注册表：CardKind ─┐   新资产：Theme(报表主题) ─┘   新运行时能力：parameters / dimensionMappings / derived measures
```

新增 Go 包（均在 `internal/report/` 下）：

| 包 | 职责 | 依赖 |
|---|---|---|
| `cardkind` | 语义卡片种类注册表（JSON 清单 + Go 校验），kind → 组件候选/方法/合同/布局意图 | `template`, `insight` |
| `blueprint` | Blueprint v1 Schema、Go 模型、校验、`Expand`（蓝图 → Definition）、`Extract`（Definition → 蓝图） | `cardkind`, `layout`, `report`, `compiler` |
| `layout` | 布局意图求解器：`Solve(intent, kinds, theme) → desktop/mobile 坐标` | `report`, `theme` |
| `theme` | 主题 v1 Schema、注册表、读取 `platform.report_theme(_versions)`、内置种子、CSS 变量导出 | — |
| `contextpack` | 面向模型的上下文包构建（指标/维度目录、画像、模板、规则） | `dataset`, `queryruntime`, `access` |
| `reportgen` | L3 编排（状态机、步骤裁决、断点续跑、预算） | 以上全部 + `reportai` + `reportinsight` + `runtime` |
| `reportai/ops` | AI 侧意图级操作合同（严格 Schema）与展开器（→ `operation.Bundle`） | `operation`, `cardkind`, `blueprint` |
| `reporteval` | 生成质量评测（结构、事实、空卡、布局、人评账本） | `reportgen` |

`reportai` 保留现有 5 个提示词合同，新增 `report-blueprint-v1`、`report-refine-v1`、`report-summary-v1`、`report-ops-v1`；
`report-plan-v1` 与 `Instantiate` 在 Blueprint 上线后进入兼容期（`/reports/ai/create` 内部改走 Blueprint，输出不变）。

## 2. 契约与 Schema

### 2.1 Report Definition 1.1（向后兼容增量）

`schemaVersion` 升为 `"1.1"`；1.0 文档读取时由 `compiler/migrate` 升级（全部新增字段可省略，缺省即 1.0 行为）。

```jsonc
{
  "schemaVersion": "1.1",
  "themeRef": { "themeId": "…", "version": "1.0.0" },          // 不再悬空：必须能在主题注册表解析
  "parameters": [                                                 // 新：报告参数
    { "name": "period", "type": "PERIOD", "grain": "MONTH", "default": { "mode": "RELATIVE", "offset": -1 } },
    { "name": "comparePeriod", "type": "PERIOD", "grain": "MONTH", "default": { "mode": "RELATIVE_TO", "ref": "period", "offset": -1 } }
  ],
  "dimensionMappings": [                                          // 新：公共维度
    { "id": "…", "name": "region", "members": [
        { "dataContextId": "ctx-a", "field": "region" },
        { "dataContextId": "ctx-b", "field": "region_name" } ] }
  ],
  "globalFilters": [ { "…": "…",
      "fieldRef": { "dataContextId": "ctx-a", "field": "region" },
      "dimensionMappingId": "…" } ],                                // 新（可选）：声明后按映射跨数据集生效
  "pages": [ { "sections": [ {
      "layoutIntent": { "kind": "FLOW" },                           // 新（可选）：节级布局意图
      "blocks": [ {
        "cardKind": "RANK",                                         // 新（可选）：语义卡片种类
        "layoutIntent": { "span": 12, "minRows": 6, "attach": null }, // 新（可选）
        "layout": { "desktop": {…}, "mobile": {…} }                 // 仍是事实坐标，求解器写入
      } ] } ] } ],
  "components": [ { "dataBinding": {
      "bindingMode": "DATASET_FIELD", "dataContextId": "ctx-a",
      "dimensions": [ { "role": "CATEGORY", "field": "region" } ],
      "measures":   [ { "role": "VALUE", "field": "revenue" },
                      { "role": "VALUE", "field": "revenue",           // 新：派生度量
                        "derived": { "kind": "PERIOD_COMPARISON", "against": "comparePeriod", "output": "RATE" } } ],
      "timeParameter": "period"                                      // 新：把报告参数绑定为该卡的时间窗
  } } ]
}
```

规则：
- `derived.kind ∈ {PERIOD_COMPARISON, SHARE_OF_TOTAL, TARGET_ACHIEVEMENT, RANK}`；`output ∈ {DELTA, RATE, VALUE}`；
  派生度量的可加性判定与来源度量一致，`SHARE_OF_TOTAL` 要求来源 ADDITIVE（沿用 `runtime/rollup.go` 的失败关闭）。
- `dimensionMappings.members[*]` 字段必须在对应数据集版本存在且 `field_role ∈ {DIMENSION, TIME}`，语义类型一致。
- `cardKind` 存在时，组件 `templateRef.type` 必须在该 kind 的候选组件内；`layoutIntent` 只是意图，坐标仍是事实，`compiler.Validate` 继续做碰撞校验。
- `Canvas` 冻结值不变（不放开自由布局）。

Go 变更：`model.go` 增 `Parameter/DimensionMapping/LayoutIntent/DerivedMeasure` 类型与校验；`ComponentOptions` 保持封闭但**新增按 kind 命名空间的 `Presentation map[string]json.RawMessage`（由清单 optionSchema 校验）**，
避免每加一个视觉属性都改 Go 结构（这是 docs/13 §2.3 指出的封闭结构体问题的解法：仍然 closed，但 closed 在清单层）。

新增 Operation（`operation/model.go`）：`PARAMETER_CREATE/UPDATE/DELETE`、`DIMENSION_MAPPING_CREATE/UPDATE/DELETE`、
`BLOCK_KIND_UPDATE`、`LAYOUT_INTENT_UPDATE`、`LAYOUT_SOLVE`（服务端按意图重算全部坐标的原子操作，可撤销）；`THEME_UPDATE` 已存在，改为真实解析主题并触发 `LAYOUT_SOLVE`。

### 2.2 Report Blueprint v1（模型可写的中间表示）

严格 Schema（每个属性必填、无条件关键字、只用本地 `$defs`，与 `aiFacingSchema` 一致），文件 `internal/report/blueprint/schemas/report-blueprint-v1.schema.json`。

```jsonc
{
  "schemaVersion": "report-blueprint-v1",
  "title": "2026年7月经营分析月报",
  "reportType": "REPORT",
  "themeCode": "corporate-light",                       // 来自 allowlist
  "parameters": [ { "name": "period", "type": "PERIOD", "grain": "MONTH", "default": "PREVIOUS" },
                  { "name": "comparePeriod", "type": "PERIOD", "grain": "MONTH", "default": "PREVIOUS_OF:period" } ],
  "datasets": [ { "alias": "pnl", "datasetVersionId": "…" }, { "alias": "ar", "datasetVersionId": "…" } ],  // 来自 allowlist，≤6
  "conformedDimensions": [ { "name": "region", "members": [ { "dataset": "pnl", "field": "region" }, { "dataset": "ar", "field": "region_name" } ] } ],
  "filters": [ { "dimension": "region", "type": "MULTI_SELECT", "scope": "REPORT" } ],
  "sections": [ {
    "title": "整体经营概览",
    "question": "本月收入、毛利、费用相对上月和目标如何？",
    "leadIn": true,                                                // 是否生成章节导语
    "rows": [                                                      // 布局意图：行 → 卡
      { "cards": [
        { "kind": "KPI", "dataset": "pnl", "measures": ["revenue"], "compare": "comparePeriod", "target": "revenue_target",
          "methods": ["CURRENT_VALUE","PERIOD_COMPARISON","TARGET_ACHIEVEMENT"], "narrative": true, "weight": 1 },
        { "kind": "KPI", "dataset": "pnl", "measures": ["gross_margin_rate"], "compare": "comparePeriod", "target": null,
          "methods": ["CURRENT_VALUE","PERIOD_COMPARISON"], "narrative": true, "weight": 1 } ] },
      { "cards": [
        { "kind": "TREND", "dataset": "pnl", "measures": ["revenue","gross_profit"], "dimensions": [], "time": "month",
          "compare": null, "target": null, "topN": null, "methods": ["TREND","MAX_CHANGE"], "narrative": true, "weight": 2 },
        { "kind": "RANK", "dataset": "pnl", "measures": ["revenue"], "dimensions": ["region"], "time": null,
          "compare": null, "target": null, "topN": 10, "methods": ["TOP_N"], "narrative": true, "weight": 1 } ] }
    ]
  } ],
  "summary": { "enabled": true, "style": "EXECUTIVE", "maxSentences": 5 }
}
```

约束（`blueprint.Validate`，全部确定性）：
- 所有 `datasetVersionId / field / themeCode / kind / method / filter.type` 必须在请求 allowlist 内（沿用 `ValidatePlan` 风格）；
- 每张卡满足其 kind 的数据合同（度量/维度数量、是否需要时间、是否需要可加）；`compare/target` 只允许 kind 声明支持的；
- `sections ≤ 30`，`cards ≤ 300`，每行 `Σweight ≤ 4`（映射到 24 列）；
- `filters[*].dimension` 必须是 `conformedDimensions` 或某单一数据集字段；
- 不含任何数值、SQL、坐标、ID。

`blueprint.Expand(bp, ctx) → report.ReportDefinition`：
1. 数据集别名 → `DataContext`（`QueryPolicy` 取默认）；
2. `conformedDimensions → dimensionMappings`，`filters → globalFilters`（附 `dimensionMappingId`）；
3. 每卡：`cardkind.Resolve(kind, contract, ctx.Profile)` 决定组件类型/版本（沿用 `answer.RecommendChart` 作为图形推荐内核）、绑定角色（`preferredRole` 逻辑迁入 `cardkind`）、派生度量、`insight` 附着区（`narrative:true` → INSIGHT zone，同 `instantiate.go:97-139`）；
4. `layout.Solve` 写坐标；
5. ID 沿用 `deterministicIDFactory`（seed 增加 blueprint 哈希）；`compiler.Normalize` 后返回。
`Expand` 是纯函数：同蓝图 + 同上下文 → 同 Definition，用作回归基线。

`blueprint.Extract(def) → Blueprint`（模板反抽）：坐标 → 行/权重（按 y 分行、按 w/24 归一为 weight）；组件 → kind（按 kind 候选反查，多义时选 `cardKind` 字段）；字段绑定原样保留；结论/摘要状态丢弃。

## 3. 布局求解器（`internal/report/layout`）

输入：节列表（每节 rows → cards：`span|weight`, `minRows`, `narrativeAttach`）、每卡 kind 的默认意图与组件 `minSize/recommendedSize`、主题密度。
输出：`Block.Layout.Desktop{x,y,w,h}` 与 `Mobile{order,heightMode,slotMode}`；保证无碰撞、不越界、满足 `minSize`。

算法（确定性）：
1. 行内分宽：`w_i = round(24 * weight_i / Σweight)`，最后一张吸收取整误差；`w_i < minSize.w` 时把该行拆成两行（贪心，稳定顺序）；
2. 行高：`h = max(minRows, recommended.h * densityMultiplier, 卡内 zone 高度和)`；同一行统一为该行最大 h（对齐底边）；
3. 结论附着：`narrativeAttach=RIGHT` 且 `w ≥ 16` 时把 INSIGHT zone 放到卡内右列（zone `columns` 分 16/8），否则放在 CONTENT 下方（现行做法）；
4. 纵向堆叠：`y` 递增；节之间不加空行（章节标题由渲染器绘制）；
5. 移动投影：`order` 按 (section, row, x) 展开；KPI 行 `slotMode=CAROUSEL`（>2 张）；表格 `heightMode=FIXED`；
6. `LAYOUT_SOLVE` 操作把结果写回；用户随后手动拖动仍是普通 `BLOCK_MOVE/RESIZE`（`layoutIntent` 保留但标记 `manualOverride=true`，再次求解需显式确认）。

不做：全局最优装箱、绝对定位、放开 24 列。

## 4. 运行时变更

1. **公共维度过滤**：`runtime/filter.go ResolveFilters` 解析出的 `ResolvedFilter` 若带 `dimensionMappingId`，在 `dataset_runner.go datasetPredicates` 中按目标 `dataContextId` 查映射成员字段替换后下推；
   没有成员的数据集不受该过滤器影响（保持现行"只作用于声明的数据集"语义，并在执行计划里标注 `NOT_APPLICABLE`）。
2. **报告参数**：`runtime.Session` 增 `parameters map[string]ResolvedParameter`（默认值按 `now` 与粒度解析，沿用 `ResolveDefaultFilterValues` 风格）；
   `timeParameter` 绑定的卡片把参数解析成时间谓词（`FilterDateRange` 语义）；`comparePeriod` 类型参数在 `derived.PERIOD_COMPARISON` 时被翻译为第二次查询或窗口计算。
3. **派生度量**：`PERIOD_COMPARISON/TARGET_ACHIEVEMENT` 在 `querybatch` 中按同一绑定发起对比期查询并在服务端合并（同一 `ExecutionTarget`，缓存键含参数）；
   `SHARE_OF_TOTAL/RANK` 在结果集内计算。全部输出进入 `ResultTable` 追加列（列名 `revenue__cmp_rate` 等），供渲染与 `insight.BuildMethodInput` 消费——结论方法因此可以直接读派生列而不重复计算。
4. **草稿执行摘要**：`POST /reports/{id}/draft/execute` 增 `summaryOnly=true`：只返回每卡 `{rowCount, empty, error, extremes, timeCoverage}`，供精修环使用（不返回明细，省 token 与带宽）。
5. **SEMANTIC_IR 不变**：仍需发布才可运行；本期 AI 生成继续只产 `DATASET_FIELD`（记录为已知限制）。

## 5. 生成编排（`internal/report/reportgen`）

状态机（每步落 `report_generation_runs` / `report_generation_steps`，可断点续跑、可审计）：

| 步骤 | 类型 | 输入 → 输出 | 失败策略 |
|---|---|---|---|
| S1 CONTEXT | 确定性 | 请求 → ContextPack | 失败即终止 |
| S2 BLUEPRINT | 模型 `report-blueprint-v1`（模板存在时为"填空"模式：模板蓝图 + allowlist） | ContextPack + 意图 → Blueprint | 校验失败重试 ≤2（回填错误清单），仍失败 → 若有模板则用模板默认蓝图，否则终止 |
| S3 EXPAND+SOLVE | 确定性 | Blueprint → Definition 1.1（草稿 r1） | 失败即终止 |
| S4 EXECUTE | 确定性 | `draft/execute?summaryOnly` | 单卡失败记录，不终止 |
| S5 REFINE | 模型 `report-refine-v1`（可选，可关） | 摘要 + Blueprint → `report-ops-v1`（仅允许 REMOVE_CARD / REPLACE_CARD_KIND / SET topN / 关闭 narrative） | 无模型：确定性规则——空卡删除、行数>阈值的 RANK 改 DETAIL |
| S6 NARRATIVES | 模型 `report-insight-v1`（现有）批量：对每张 `narrative:true` 卡 `derive → generate → verify` | 结论落 `insight` 存储 | 校验失败的卡不写结论、INSIGHT zone 置隐藏（`HIDDEN`），记录原因 |
| S7 SUMMARY | 模型 `report-summary-v1` | 章节内已验证结论 + 证据 → 章节导语；全部导语 → 报告摘要（仍是标记写作） | 失败则无摘要，不阻塞 |
| S8 FINALIZE | 确定性 | 生成日志、Provenance（`createdFrom=AI`, `aiRunIds`, `promptVersions`, blueprint 哈希） | — |

- 并发：S6 按卡片并发（≤ `RuntimePolicy.MaxConcurrentQueries`），S4 复用 `querybatch`；
- 预算：每次生成模型调用上限（S2 ≤3、S5 ≤1、S6 ≤ 卡数、S7 ≤ 节数+1），超预算降级为确定性路径；
- 落草稿方式：S3 结果通过 `REPORT_CREATE`（AI 来源）一次写入；S5/S6/S7 通过 Operation 追加修订，因而可撤销；
- 事件：`report.generation.step` 进 SSE/轮询接口供前端进度条。

`report-summary-v1` 提示词约束与 `narrativeSystemPrompt` 一致（禁数字/对象名，只写 `{{fact:}}/{{field:}}` 标记，且标记必须来自输入的已验证证据集合），校验器复用 `answer.Verifier`；
摘要 artifact 存 `insight` 存储，`insightRole=SUMMARY|LEAD_IN`。

## 9. 测试、评测与验收

**单元 / 契约**
- `blueprint`：Schema 严格性测试（无 `if/then/else/dependentRequired/$ref` 外部引用；每个属性在 `required` 中）；`Expand` 幂等与确定性（同输入同哈希）；`Extract(Expand(bp)) ≈ bp`（往返测试，允许坐标信息丢失）；
- `cardkind`：每 kind 的合同 × 组件候选覆盖 `template.Registry`；kind 升级走 `CheckUpgrade` 同规则；
- `layout`：随机蓝图（property test）→ 无碰撞、不越界、满足 minSize、移动 order 连续；密度切换只改 h 不改相对顺序；
- `runtime`：跨数据集映射过滤下推；派生度量可加性失败关闭（复用 `rollup_test.go` 风格）；参数解析边界（月末/闰年/时区）；
- `reportgen`：状态机每步失败注入；无模型提供方时 S2 用模板蓝图、S5 用规则、S6/S7 跳过，仍产出可发布草稿；
- `reportai/ops`：每种 op 的展开与守卫（禁止 `DATA_CONTEXT_*`、删除上限）。

**评测（`reporteval`，进入 CI 的黄金集）**
- ≥30 例 `{intent, datasetVersionIds, template?}` → 断言：蓝图校验通过率、空卡率 ≤5%、结论校验通过率 100%（未通过者不出现）、布局无重叠、每节 ≥1 张有结论的卡；
- 人评账本：两名具名评审对生成稿打分（结构合理性 / 结论有用性 / 视觉），沿用 docs/06 规则 23 的"人的判断由人提供"纪律；
- 提示词或 Schema 版本变更必须跑黄金集，指标回退阻断合入。

**验收（对应 docs/13 §9 里程碑）**
- M1：手写蓝图 → `expand` → 发布成功；`/reports/ai/create` 改走蓝图后 L2 回归不退化；
- M2：同一蓝图切 3 套主题：`draft/execute` 无错误、`Validate` 无碰撞、移动投影自动、导出样式一致；
- M3：黄金集空卡率、结论通过率达标；参数改动后所有 `timeParameter` 卡与结论联动重算；
- M4：`ai/preview` 在真实模型下稳定消费 `report-ops-v1`；模板反抽 + 再生成往返成功；评测集入 CI。
