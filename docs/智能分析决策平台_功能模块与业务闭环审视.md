## 1. 定位纠正

本项目的统一定位修正为：

> **智能分析决策平台**是面向业务人员的可信分析工作台。它以受治理的数据、指标和语义资产为底座，以智能问数和智能报告为两个核心分析入口，将「发现问题—获得证据—沉淀分析—形成决策—跟踪行动—复盘结果」连成闭环。

定位包含四个层次：

1. **数据可用**：数据源、数据集、数据质量和权限可治理。
2. **分析可信**：指标、维度、时间、证据、结果和叙述可回放。
3. **分析可复用**：一次问数可保存、共享、加入报告；已认证报告可反哺问数。
4. **决策可闭环**：关键结论可形成决策记录和行动项，并通过后续指标复盘验证效果。

### 1.1 明确边界

- 平台是「决策支持与协同」平台，不是业务交易或流程执行系统。
- 平台可记录责任人、截止时间、行动状态和结果指标，但不自动在 ERP、CRM等外部系统执行调价、下单、转账等高风险操作。
- 「智能」不代表 LLM 可绕过语义发布、数据权限、查询编译、结果校验或人工审批。
- 95% 正确率仍只对已治理业务域、已支持问题类型和密封黄金集成立，不得扩大为任意数据或任意问题。

## 3. 闭环判定口径

一个功能模块仅在同时满足以下条件时才能称为「完整可闭环」：

1. 有明确业务触发人、处理人、审批人和责任 Owner。
2. 有可执行的主路径，不依赖手工改库或临时脚本。
3. 异常、拒绝、撤回、超时、降级和重试有可见出口。
4. 关键写操作受权限、版本、幂等和审计约束。
5. 产物能被下游消费，并能在变更、失效或下架时通知下游。
6. 结果有可量化验收标准，且失败会回流为工单、修复候选或下一轮计划。

实现状态采用四层口径：

| 层级 | 定义 |
|---|---|
| BE | 数据模型、领域服务、API/Worker 和自动化测试 |
| FE | 真实 API 接线的用户界面，不以 fixture/快照/提示文案替代执行 |
| E2E | 在真实数据库和应用进程上从触发走到终态，包括一条异常支路 |
| BIZ | 使用真实 Owner、业务资产、黄金集、SLA 和目标环境完成签署 |

## 5. P01～P15 完整业务闭环

### P01 平台、组织、租户和权限

**角色**：普通用户、领域管理员、平台管理员、安全管理员。

**主流程**：

1. 员工注册或由企业身份源创建账号，系统验证唯一身份。
2. 用户查看可申请的业务域，提交领域准入申请和用途。
3. 领域管理员审批；敏感域按策略增加安全会签。
4. 系统分配领域成员身份和对象权限，写入不可变审计记录。
5. 用户登录后固定当前业务域，进入分析首页；切换领域时重新签发上下文。
6. 每次资产读写与数据查询同时校验租户、领域、对象和数据范围。
7. 角色或组织变更时，重算有效权限，失效会话与超范围共享。
8. 员工离职或账号停用时，立即终止会话，将未结工单、报告和决策转交 Owner，保留审计。

**异常与终态**：拒绝申请必须留原因；最后一位领域管理员不得移除；领域停用前必须输出资产影响清单。闭环终态为「权限生效/已拒绝/已撤销」，且所有资产有合法 Owner。

**当前校验**：注册、登录、领域申请、管理员、用户领域、审批、账号停用和日志已有前后端主链；资产 Owner 批量转交、企业组织树/SSO 和业务首页未形成闭环。

### P02 数据源、元数据和数据资产

**角色**：数据配置人、数据 Owner、领域管理员、安全管理员。

**主流程**：

1. 数据 Owner 提出分析需求，确定业务域、数据类型、刷新 SLA 和敏感等级。
2. 配置数据源和加密凭证，依次执行网络、鉴权、权限和最小读取测试。
3. 测试通过后提交发布申请；审批人检查用途、权限和样本同意。
4. 发布后触发元数据发现，沉淀表、字段、主键、行数、样本和结构快照。
5. 数据 Owner 完善业务名、描述、标签、敏感等级和质量期望，处理 AI 建议。
6. 通过数据资产目录将可用表交付 P03，不合格资产进入整改。
7. 定时增量同步元数据；结构、凭证或连通性变更时生成差异与下游影响。
8. 数据源下架前阻断新引用，迁移或下架下游数据集，完成后彻底撤销读权限。

**异常与终态**：连接测试按阶段返回可诊断错误；凭证过期后禁止刷新；结构破坏性变更使资产进入 `STALE/BLOCKED`。闭环终态为「可用资产已发布/已拒绝/已安全下架」。

**当前校验**：数据源配置、连接测试、发布审批、元数据和 AI 完善已有实现；跨页变更影响处置和下架前的业务迁移清单需端到端验收。

### P03 数仓与数据集建模

**角色**：数据开发、数据 Owner、数据集审批人、语义管理员。

**主流程**：

1. 从 P02 选择已发布资产，声明目标层级、粒度、刷新策略和 Owner。
2. 在画布编排数据节点、关联、过滤、变换、分组和输出，或由 AI 生成可审查方案。
3. 预览节点和最终输出，检查循环、字段、粒度、Join 基数和成本。
4. 保存版本化草稿，提交精确草稿发布申请。
5. 审批通过后生成不可变发布版本，触发物化 DAG 和数据质量检查。
6. 成功后更新数据快照版本、血缘和可用性，将 DWS/ADS 交付 P04～P08。
7. 定时运行、告警和重试；连续超时或质量失败时停止下游刷新。
8. 变更时做依赖影响、发布新版本并平滑切换；回滚是复制历史修订为新草稿，不改写历史。

**异常与终态**：无安全 Join 路径、无输出节点或成本超限时不得发布；物化任务可取消、重试和从检查点恢复。闭环终态为「已发布且物化可用/已拒绝/已下架」。

**当前校验**：数据集画布、AI 方案、草稿、预览、发布审批、物化、批量运行/停止、历史与回滚已有主链；真实仓库增量策略和生产 SLA 仍需 BIZ 验收。

### P04 语义模型与实体

**角色**：语义管理员、数据 Owner、业务域 Owner。

**主流程**：

1. 从已发布 DWS/ADS 发现语义模型候选，选择对应业务域。
2. 定义实体、主键、粒度、模型角色、时间合同和数据 Owner。
3. 映射数据集与字段，定义实体间关系、基数、有效期和安全 Join 策略。
4. 执行引用完整性、粒度、Fanout、时间和权限校验，输出人可读问题清单。
5. 数据 Owner 确认技术映射，业务域 Owner 确认业务语义，通过后保存 DRAFT。
6. 与 P05～P07 一起进入 P08 Release；激活后成为问数和报告的固定依赖。
7. 上游数据集或关系变更时生成影响分析，未迁移完不得废弃旧版本。

**异常与终态**：多对多未指定安全策略、粒度不一致、无 Owner 或引用未发布数据集均失败关闭。闭环终态为「已激活/已退回草稿/已受控废弃」。

**当前校验**：领域模型、存储、校验、发布包和 API 已实现；业务无编辑、评审、差异和影响页面。

### P05 指标与度量中心

**角色**：指标 Owner、语义管理员、数据 Owner、评测人员。

**主流程**：

1. 从数据集、现有报告或重复问题发现度量/指标候选。
2. 创建草稿，定义业务名、口径、Formula AST、粒度、单位、币种、时间策略和默认过滤。
3. 声明可加性、半可加时间聚合、不可加维度、适用维度和正反例。
4. 执行公式、除零、空值、粒度、单位、可加性和样例计算校验。
5. 指标 Owner 审批业务口径，数据 Owner 审批数据映射，生成认证版本。
6. 纳入 P08 发布和黄金集回归；激活后可被问数、报告和决策复盘引用。
7. 线上持续观测命中率、结果异常和用户反馈，候选修复不直接修改生产。
8. 口径变更时新建版本并通知影响报告/保存问题/决策；废弃前必须配置替代指标或终止理由。

**异常与终态**：可加性未确认、Formula 不可编译、无 Owner 或样例不等价时不得认证。闭环终态为「已认证/已退回/已迁移废弃」。

**当前校验**：存储、Formula、可加性、时间、编译和建议器已实现；指标 Owner 可用的建设、批量补录、审批与影响页面缺失。

### P06 维度、成员和层级中心

**角色**：维度 Owner、语义管理员、安全管理员。

**主流程**：

1. 从已发布字段发现维度候选，定义维度角色、稳定键和显示字段。
2. 执行有界画像，计算基数、空值、变化率、样例和敏感性。
3. 选择 `FULL/ON_DEMAND/EXACT_ONLY/NONE` 成员策略，不得对高基数或敏感成员无界向量化。
4. 维护规范值、显示名、别名、负向上下文、层级、父子关系和有效期。
5. 执行重复、冲突、越权披露、层级成环和成员所属校验。
6. 维度 Owner 审批后进入 P08，发布时构建精确、词法和允许的向量索引。
7. 增量监测新成员、别名未命中和基数越界，超限时自动降级策略并通知 Owner。

**异常与终态**：敏感成员禁止 label-bearing 召回；别名冲突必须由 Owner 裁定；索引不一致时发布失败关闭。闭环终态为「已发布且索引就绪/已退回/已降级」。

**当前校验**：画像、成员策略、敏感门禁、规范化、别名和索引后端已实现；Owner 处理待办、层级维护和策略降级页面缺失。

### P07 业务词典、认证问法和 KPI Bundle

**角色**：业务域 Owner、语义管理员、指标/维度 Owner、运营人员。

**主流程**：

1. 从历史问题、报告、反馈和业务语料收集术语、缩写、同义词和认证问法候选。
2. 运营人员建立词条，绑定稳定语义 ID，补充正向/负向上下文和适用域。
3. 对重复、跨对象歧义、权限泄漏和最长匹配冲突做自动校验。
4. 对「经营怎么样」等宽泛问题维护 KPI Bundle，明确指标顺序、并发上限和降级行为。
5. 对候选问法运行理解、绑定和结果回归，Owner 审批后进入 P08。
6. 发布后只作为受治理候选证据，不能覆盖指标口径或权限。
7. 线上未命中、高澄清率和重复问题进入主动学习，人工审批后生成新版本。

**异常与终态**：用户反馈不得直接写生产词典；报告自由文本不得成为语义事实。闭环终态为「已认证/已拒绝/已废弃并保留影响」。

**当前校验**：词典、匹配、KPI Bundle、保存问题和报告种子后端已实现；词典/KPI/认证问法的运营页面缺失。

### P08 语义发布、评测和审批

**角色**：语义管理员、独立评测人员、指标/维度/数据 Owner、发布审批人。

**主流程**：

1. 从 P04～P07 选择精确草稿版本，生成内容哈希固定的 Release Candidate。
2. 执行引用、Owner、时间、可加性、权限、敏感性和数据质量静态校验。
3. 将发布包投影到检索与 NebulaGraph，比对事实哈希、索引哈希和图哈希。
4. 运行开发、验证、密封和安全集，生成阶段指标、Wilson 下界和错误预算。
5. LLM 可生成评审摘要，但门禁结果必须从数据库事实重算。
6. 两位职责分离的审批人完成审批，系统在单事务中切换 ACTIVE。
7. 新版本先经 Shadow/Canary，持续观测正确性、澄清率、延迟、安全和成本。
8. 回归或线上指标失败时停止扩容、回滚 ACTIVE；被历史资产引用的 Release 进入 RETAINED。

**异常与终态**：无业务评测事实、投影不一致、同人双签或门禁未过时不得 ACTIVE。闭环终态为「ACTIVE/已拒绝/已回滚/已保留」。

**当前校验**：发布状态机、投影、评测、双人审批、激活、保留和回滚后端已实现；无发布中心前端，真实密封集、Shadow/Canary 与审批人尚未 BIZ 验收。

### P09 分析入口与智能问数工作台

**角色**：业务用户、分析师、业务 Owner。

**主流程**：

1. 用户在分析首页看到待关注 KPI、最近分析、报告、决策和任务，选择已固定业务域。
2. 用自然语言提问，或从认证问题、保存问题、报告组件发起。
3. 系统完成范围分类、上下文合并、理解、检索、联合绑定和图路径验证。
4. 若只存在一个局部歧义，展示带定义、Owner、版本和质量的定向澄清；用户选择后继续同一 Run。
5. 系统编译、预检、执行和校验结果/叙述，在预算内自我纠错。
6. 返回直接答案、PARTIAL/NO_DATA、降级结构化答案、澄清或正确拒答。
7. 用户继续追问，系统只继承已认证绑定；Release 漂移时要求确认。
8. 用户将结果保存、收藏、团队共享、加入报告、转为决策或提交反馈。

**异常与终态**：明细列表转取数申请；配额超限显示恢复时间和申请入口；澄清超时可恢复或重新发起。终态为「已回答/已澄清/已拒答/已取消」，且用户有下一步动作。

**当前校验**：Question API/SSE、澄清、Release 漂移、范围拒答、结果和反馈已真实接线；会话历史、常用问题和若干分析展示仍来自快照，保存/共享/加入报告/决策无前端。

### P10 查询结果、证据和追问

**角色**：业务用户、分析师、审核人。

**主流程**：

1. 打开答案 Artifact，检查 Release、数据时点、策略范围和结果哈希。
2. 首屏显示结论、核心数值、时间范围、单位、比较和降级状态。
3. 用户在规则允许的图表与表格间切换，查看排序、TopN、Other、合计和不可加提示。
4. 展开证据面板，核对理解、口径、维度、图路径、数据质量、新鲜度和权限摘要。
5. 通过追问完成分组、对比、异常定位或改变时间，每一步保留父子链。
6. 依用途导出 CSV/Excel/图片，或保存问题、共享团队、加入报告和转为决策。
7. 结果不正确时提交结构化反馈；超范围明细需求转取数申请并预填上下文。
8. 上游版本或数据失效时标记历史结果，重放时按当前权限重新执行。

**异常与终态**：大结果走异步导出；叙述校验失败时只展示结构化答案；查看者无权时不泄漏资产标题和成员。闭环终态为「已消费/已沉淀/已反馈/已申请」。

**当前校验**：结果、图表、表格、证据、叙述降级、结构化反馈和明细申请已有页面；问数导出、保存/共享、加入报告和决策仍缺真实动作。

### P11 配置化智能报告设计器与运行时

**角色**：业务分析人员、报告 Owner、审批人、报告查看者。

**主流程**：

1. 用户从模板中心、空白报告、问数结果或已有报告副本创建报告。
2. 选择报告类型、Owner、业务域、频率、主题和受众；AI 生成结构计划。
3. 系统确定性实例化 Report Definition，用户在画布调整页、章节、区域、槽位和组件。
4. 为组件绑定 Semantic IR 或允许的 Dataset Field，配置筛选、联动、时间和移动端降级。
5. 生成 Evidence Bundle 和智能结论；局部 AI 修改以 Report Operation 差异预览后应用。
6. 预览当前查看者权限、筛选交互、组件异常、打印和移动端，完成发布前校验。
7. 发布生成不可变版本与制品，查看者按当前权限加载并执行数据。
8. 报告支持命名用户/角色分享、受控导出、订阅/定时生成，不允许匿名扩权。
9. 发布后持续观测组件状态、数据新鲜度和使用情况；新修订重新发布，可回滚或下架。

**异常与终态**：单组件失败不拖垮全报告；组件版本、语义依赖或叙述校验失败时阻断发布或局部降级。终态为「草稿/已发布/已回滚/已下架」，历史不可改写。

**当前校验**：Report Definition、Operation、布局、模板、AI、Insight、运行时、筛选、发布、回滚、导出、分享、权限和上下架后端已实现。前端只有资产列表/权限/上下架的部分真实接线；创建、设计、发布、版本、筛选执行、数据组件、导出和分享按钮尚未真实接线，订阅/定时生成也未建设。

### P12 问数与报告资产融合

**角色**：业务用户、报告编辑者、报告 Owner、语义 Owner。

**问数入报告流程**：

1. 用户在已验证答案上选择「加入报告」。
2. 系统只列出当前用户可编辑、同租户且同业务域的报告草稿。
3. 根据结果 Schema、意图、可加性和布局空位推荐组件、标题和位置。
4. 生成固定 Question Run、Semantic IR、Release 和 Evidence 的 AddToReport Intent。
5. 用户预览差异并确认，后端以幂等 Report Operation 写入新修订。
6. 报告编辑者可调整，发布时重新验证绑定。

**报告反哺问数流程**：

1. 报告发布后提取 `SEMANTIC_IR` 组件、筛选、问题种子和图表推荐。
2. 校验指标/维度认证、证据可追溯、数据质量和报告权限。
3. 报告 Owner 完成单人资产认证；`DATASET_FIELD` 和自由文本不进入生产绑定。
4. 认证资产进入检索/图投影，只提供候选先验，不改写指标口径。
5. 语义 Release 变更时输出报告影响和升级预览；确认后重编译并新建草稿修订。
6. 报告下架、权限变更或认证撤销时，立即从有效候选中移除并保留审计。

**闭环终态**：「结果已写入报告修订/意图已取消」，以及「报告资产已认证/已拒绝/已撤销」，且两个方向均可追溯原始 Artifact。

**当前校验**：两个方向的后端服务、存储、幂等、权限、图表推荐和升级已实现；问数、报告两侧都没有真实用户入口和差异确认页面。

### P13 反馈、主动学习和运营

**角色**：业务用户、运营人员、语义/数据 Owner、评测人员。

**主流程**：

1. 用户对问数、报告、取数申请或决策提交结构化反馈，固定对象版本与运行证据。
2. 系统去重、聚类并生成反馈工单，按严重程度、业务域和问题类型分派。
3. 运营人员复现问题，规则和 LLM 将原因归因到数据、指标、维度、成员、时间、编译、执行、叙述或权限。
4. 系统只生成修复候选或开发工单，Owner 确认修复方案和风险。
5. 修复进入对应 P02～P08/P11 草稿流程，执行原问题、专项集与全量密封回归。
6. 门禁通过后按发布流程上线，工单链接修复版本和验证证据。
7. 系统通知反馈人处理结果，跟踪复发率、SLA、闭环率和修复收益。
8. 高频明细申请、未识别问法和重复报告自动转为资产建设候选。

**异常与终态**：不可复现需补充证据；无权运营人员不得查看敏感值；用户反馈永不直接修改生产。终态为「已验证解决/不修复已说明/合并重复/等待用户」。

**当前校验**：问数反馈提交、反馈工单、归因、主动学习、密封集、误差预算和明细申请后端已实现；运营管理页、用户通知和跨对象统一反馈入口缺失。

### P14 系统管理、监控和成本治理

**角色**：平台管理员、运维、安全、业务域 Owner、财务/成本 Owner。

**主流程**：

1. 上线前配置 Provider、Worker、业务域开关、四级配额、查询预算、容量阈值和数据保留。
2. 对 Question Run、Report Run、投影、物化、导出和评测建立统一 Trace、日志、指标和成本记录。
3. 业务看板按租户/领域/用户/功能显示可用性、延迟、质量、正确性、配额和价值指标。
4. 超阈值时告警并生成事件，使用 Run ID 定位 Artifact 和上下游影响。
5. 系统按预案限流、熔断、切换供应商、降级图或阻断不可信路径，不以猜测继续。
6. 运维执行恢复，重放受影响任务，验证业务指标恢复后关闭事件。
7. 复盘根因、影响、检测窗口和改进项，转为配置、容量、测试或产品 TODO。
8. 定期完成 PostgreSQL 恢复、Nebula 重建、制品恢复和容量压测，对成本/价值比调整策略。

**异常与终态**：重要配置缺失时生产失败关闭；80% 配额提示、100% 阻断高成本新运行；备份「成功」不等于恢复「验收」。终态为「事件已恢复并复盘/风险已接受」。

**当前校验**：结构化观测、质量/成本汇总、配额、限流以及 AskData 灾备脚本和压测框架已实现；报告运行/导出/定时分发与未来决策任务尚未纳入平台级容量和恢复演练，也无完整运营看板/配额管理页，目标环境灾备、容量和生产 POC 未执行。

### P15 决策协同与行动复盘

**角色**：决策发起人、决策 Owner、审批人、行动责任人、复盘人。

**主流程**：

1. 用户从问数答案、报告组件、智能结论或手工入口创建决策草稿。
2. 系统固定来源 Artifact、指标/维度/时间、语义 Release、数据时点和查看者权限摘要。
3. 发起人填写问题、备选方案、决策、预期效果、风险、Owner、截止时间和复盘指标。
4. 根据金额、敏感性或领域策略提交一人/多人审批；拒绝必须记录理由。
5. 审批通过后拆分行动项，为每项配置责任人、截止时间、交付物和状态，通知相关人。
6. 责任人更新 `TODO/DOING/BLOCKED/DONE/CANCELED`，阻塞和超期会逐级提醒决策 Owner。
7. 复盘日期到达时，系统按当前权限重新执行固定指标或打开对应报告，展示基线、当前值和变化。
8. 复盘人判定「达成/部分达成/未达成/无法归因」，记录实际影响和经验。
9. 已完成行动和结果复盘后关闭决策；未达成可重新打开、新建行动或发起新一轮分析。

**异常与终态**：来源资产下架或权限变更不删除历史证据引用，但未授权人不可读取原始数据；语义口径变更时显示漂移而不改写原决策。终态为「已关闭/已拒绝/已取消」，并有完整复盘或终止理由。

**当前校验**：当前代码无 Decision、Action Item、Decision Evidence、Outcome Review 的存储、服务、API、页面和测试，是定位修正后的最大新增缺口。
