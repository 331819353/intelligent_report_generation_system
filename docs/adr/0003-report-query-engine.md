# ADR-0003：报表查询面不引入 Cube Core

- 状态：Accepted
- 日期：2026-08-03

## 决策

第一版不引入 Cube Core。现有 `querycompiler`、`queryruntime`、指标发布版本、数据策略与物化链路继续作为唯一查询数据面。

报表发布时只固定指标版本和数据集版本；浏览器永远不能上传 SQL。正式 Query Batch 必须从可信发布 JSON 的卡片 ID、全局筛选和交互上下文重新生成语义查询，并将 tenantId、策略哈希、指标版本、标准化筛选和数据新鲜度纳入查询指纹。

## 当前实现

草稿和发布版本均提供 Query Batch。服务端从可信 Card DSL 固定精确指标版本，编译全局/静态/交互筛选并调用现有指标预览执行器；浏览器交互只提交交互 ID 和点击值。批次有卡片数及并发上限，单卡隔离错误，进程内 L1 缓存带 TTL 抖动并通过 Singleflight 合并并发相同请求。

Redis L2、策略哈希/新鲜度水位接入、租户公平队列、stale-while-revalidate 和发布预热仍是进入容量验收前的必做项，当前实现不冒充这些生产能力。

## 重新评审条件

满足任一条件时重新评估 Cube Core 或独立查询服务：

- 跨数据源语义查询无法由现有编译器稳定表达；
- 缓存、Singleflight、租户公平队列或预聚合无法达到容量目标；
- 查询面的扩缩容或发布周期明显不同于控制面；
- 查询洪峰影响草稿保存和发布 SLO。

在重新评审前，不维护第二份指标定义，也不让报表 DSL 绑定具体查询引擎。
