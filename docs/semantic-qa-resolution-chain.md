# 智能问答指标定位链路

## 目标

用户问题必须先定位业务领域和治理后的指标，再在该指标允许的维度范围内匹配
维度值，最后锁定指标版本绑定的精确数据集版本和 ACTIVE 物化。LLM 只负责
对已发布指标候选做意图重排，不得选择物理表、拼接 SQL 或用维度值反向猜指标。

## 五段式解析链路

1. **意图识别**：确定 `METRIC / TREND / COMPARISON / RANKING ...`，
   同时确定时间窗口、排序等结构化合同。原问题只在本次请求内使用。
2. **领域与指标定位**：先按 ODS 继承的有效领域分区，再从当前
   `PUBLISHED` 指标及其 current published version 召回最多 12 个候选。
   指标名称/别名的词法与向量相似度组成混合召回；LLM 只能复制候选中的
   指标编码。候选不足或并列时拒绝猜测。
3. **维值决策图**：指标版本先固定 `datasetVersionId`。只在该指标版本具有
   `VERIFIED` 且非 `UNSAFE` 兼容关系的维度中，以租户内成员值/别名索引做
   词法与向量混合匹配。每命中一个维度值就收紧当前状态，再从剩余兼容维度中
   选择下一分支；最多生成 512 个问题片段，不把成员值发送给外部模型。
4. **数据集锁定**：数据集不是由 LLM 或全库成员搜索决定，而是由已发布
   指标版本的不可变绑定唯一确定。维度值只能验证和收紧这个已锁定范围，
   不能把查询切换到另一数据集。
5. **执行门禁**：固定同一语义图 generation，证明
   `指标 → 维度/成员 → 精确数据集版本 → ACTIVE 物化 → 上游血缘`，
   生成 path hash。执行前再次核对指标、版本、兼容关系、物化、权限和水位。

## 决策图的存储模型

“收入 → 区域 → 日期 → 产业”及其不同提问顺序不分别保存为物理树，也不对
整条排列链路做向量化。若有 `n` 个维度，预生成所有排列会接近 `n!`，还会在
新增维度或成员时大面积失效。系统保存的是可复用事实，查询时动态形成决策 DAG：

- PostgreSQL 保存领域、指标版本、维度、成员、指标—维度兼容边和成员别名；
- `metric_semantic_documents` 只保存并向量化指标名称、别名和口径文本；
- `dimension_member_semantic_documents` 只保存并向量化非敏感、低基数、
  `FULL` 策略的维度成员值；
- pgvector HNSW 与规范化值/别名 B-tree、trigram 共同完成混合召回；
- 当前查询状态只含已选指标、已命中维度及剩余兼容维度。用户先说“产业”就先
  走产业分支，先说“区域”就先走区域分支，最终收敛到同一组规范条件；
- Redis 只适合缓存多轮会话的临时决策状态，不是权威目录；当前规模无需引入
  Neo4j。只有跨领域、多跳关系探索成为独立产品能力时才评估图数据库。

最终计划保存的不是 SQL，而是服务端生成的条件文档：

```json
{
  "domain": "运营",
  "metricCode": "income",
  "metricVersionId": "metric-version-id",
  "datasetVersionId": "dataset-version-id",
  "dimensions": [
    {"dimensionCode": "region", "dimensionId": "region-id", "memberKey": "east"},
    {"dimensionCode": "industry", "dimensionId": "industry-id", "memberKey": "food"}
  ],
  "timeRange": {"start": "2026-06-01", "endExclusive": "2026-07-01"}
}
```

数据库查询只能由受信编译器根据指标定义、字段合同和这份条件文档参数化生成。

## 排序与歧义规则

- 指标名称或编码精确命中优先；向量相似只能进入候选，不能直接成为结论。
- 同一维度命中多个不同成员时，不擅自缩减为一个值；在集合过滤合同完成前
  返回 `MEMBER_AMBIGUOUS`。
- 同一个成员值命中多个兼容维度时，只有问题明确包含唯一维度名称/编码才能
  消歧，否则返回 `MEMBER_AMBIGUOUS`。
- 不同维度各命中一个成员时可形成复合过滤，每个维度分别验证指标兼容关系。
- 没有维度条件的纯指标问题跳过维值阶段，不为“所有、数量、总数、月份”等
  通用或时间语言制造成员过滤。

## 性能边界

| 阶段 | 上限/索引 | 说明 |
| --- | --- | --- |
| 指标候选 | Top 12 | 主表保证清单完整，语义文档和向量延迟不阻断精确名称查询 |
| 成员片段 | 最多 512 | 词法与成员值向量混合召回，不做成员全文外发 |
| 兼容维度 | 最多 32 | 先按精确指标版本、数据集版本和安全兼容边限域 |
| 成员候选 | 最多 33 | 超出或无法唯一化即失败关闭 |
| 图路径 | 调用方与租户配置共同限制 | 默认最多 8 跳，且只读取单一 READY generation |

## 可观测性

`QueryPlan.resolution` 返回五个不含敏感原值的阶段：

- `INTENT_RECOGNITION`
- `DOMAIN_CATALOG`
- `METRIC_CATALOG`
- `DIMENSION_MEMBER`
- `DATASET_LOCK`

每一步记录状态、候选数、选中编码或稳定决策码。问题原文和成员原值不写入
计划；计划只保存 question hash、成员证据 ID、指标/数据集/物化版本和路径证据。
