# 智能报告生成（LLM 自主生成报告）产品设计

> 状态：设计稿 v1（2026-08-18）。本文回答三个问题：现有"配置化 + 通用卡片 + 视觉模板 + 拖拽布局 + 数据集绑定 + 筛选器"底座
> 的卡点在哪里；离"LLM 自行生成报告"还差什么；产品上应该长成什么样。配套开发设计见 docs/14。
> 现状依据：`internal/report/{model.go,reportai,insight,reportinsight,runtime,template}`、`web/src/report/{designer,render,templates}`、docs/12。

## 0. 一页结论

底座的六条规划**方向正确且大部分已经落地**（Report Definition 1.0 JSON、13 个组件清单、24 列网格拖拽、
数据集字段绑定与合同校验、多层作用域筛选器、发布链）。但它是一套**为"人手工搭"设计的底座**：
JSON 以布局坐标为骨架、以展示组件为叶子，语义（这张卡回答什么问题、用哪个指标口径、和上一张卡是什么关系）没有一等位置。
LLM 恰恰擅长语义、不擅长坐标；所以要让模型自主生成报告，缺的不是"再多几个卡片类型"，而是**在现有 JSON 之上加一层模型可写、
服务端可确定性展开的"报告蓝图"（Blueprint）**，并把视觉主题、布局求解、公共维度、报告参数、探索执行、批量结论、评测门禁补齐。

六条规划对照的结论（细节见 §2）：

| 规划 | 现状 | 主要卡点 |
|---|---|---|
| ① 配置化驱动 | ✅ `report-definition-v1`，前后端同一份 JSON | JSON 是"布局树"，不是"叙事树"；对 AI 不友好（操作 Schema 无法被模型消费） |
| ② 通用卡片 | ◐ 有 13 个**展示组件**（折线/柱/饼/表/指标卡/富文本…），有 14 种**分析方法** | 缺"结论卡/对比卡/排名卡"这一层**语义卡片**，LLM 只能直接挑图表类型 |
| ③ 视觉模板 | ✗ `themeRef` 是悬空引用（写死 `theme_corporate_light`），颜色写死在 `report.css` | 没有主题资产、没有 token、渲染器不消费主题 |
| ④ 拖拽布局 | ✅ 网格 + 碰撞消解 + 桌面/移动双布局 | 坐标是唯一真相，没有布局意图层；AI 生成只会纵向堆一列 |
| ⑤ 卡片绑定数据集 | ✅ 字段角色 + 合同 + 可加性失败关闭 | 绑的是"字段"不是"指标"；派生度量（同环比/占比/达成率）无处声明；AI 生成只允许一个数据集 |
| ⑥ 筛选器共享维度 | ◐ 筛选器有五级作用域 | 只在**同一数据集**内生效（`dataset_runner.go` 跳过其他 DataContext 的过滤器）；无公共维度映射；无报告参数 |

## 1. 目标与分级

| 级别 | 定义 | 现状 |
|---|---|---|
| L0 手工 | 人拖卡片、点绑定、写结论 | 已完成（docs/12） |
| L1 AI 辅助 | 单点：识别度量维度、写单卡结论、发布评审说明 | 已完成 |
| L2 AI 起稿 | 一句意图 → 结构 + 卡片 + 绑定，结论仍逐卡手动生成，布局单列 | 已有 `POST /reports/ai/create`，可用但产出质量弱 |
| **L3 AI 成稿（本文目标）** | 一句意图（+ 可选模板/参数）→ 完整可发布草稿：多数据集、语义卡片、自动排版、主题、全部结论与摘要已生成并通过事实校验，人只做审阅与发布 | **待建** |
| L4 AI 运营 | 定时按参数重跑、发现异动自动改写结论并推送 | 之后 |

L3 的验收口径（产品级）：
- 从输入意图到"可预览的完整草稿"≤ 90 秒（P50），期间无需人工输入；
- 生成草稿的空卡率（执行无数据/失败的卡片占比）≤ 5%，结论事实校验通过率 100%（未通过者不出现）；
- 生成草稿的"人工调整量"（发布前 Operation 数）中位数 ≤ 5；
- 所有约束不放松：LLM 零 SQL、结论只写标记、证据只由服务端派生、主链不硬依赖模型（docs/06 §4 规则 1/6/17/20/21）。

## 2. 现状评估：卡点与不合理之处

### 2.1 配置化驱动（规划①）

已成立的部分：`ReportDefinition{metadata, templateRef, themeRef, canvas, dataContexts, globalFilters, pages→sections→blocks→zones→slots, components, interactions, runtimePolicy}`；43 种受控 Operation；编辑/预览/运行同一渲染器。

卡点：
1. **JSON 的骨架是布局而不是叙事。** 一张卡在 JSON 里是 `Block(x,y,w,h) → Zone(heightMode,fr…) → Slot(grid) → Component(templateRef, dataBinding, options)`
   四层结构，坐标字段全部必填。它精确描述"画在哪"，但不描述"为什么有这张卡、它回答什么问题、它和上下卡片的关系"。
   模型生成时最不该做、也做不好的事正是算网格坐标；模型最擅长的"叙事结构与分析意图"在 JSON 里没有落点
   （`Section.Name` 与 `Component.Options.Title` 是仅有的语义字段）。
2. **对模型不友好。** `report-operation-v1` 因 if/then/else、dependentRequired、跨文件 `$ref` 不满足严格结构化输出合同，AI 改稿至今不可用（docs/12 §6）。
   直接让模型写 Definition 全量 JSON 也不现实（closed schema、ID 体系、双端布局）。
3. **模板与 Definition 割裂。** `TemplateReference` 有 structure/layout/narrative 三个版本字段，但没有对应的资产库；
   模板中心 `/report-templates` 的"分析思路模板"（`analysisTree`：CONCLUSION_OUTPUT / METRIC_DISPLAY / ANALYSIS_OBJECTIVE / DATA_SCOPE /
   ANALYSIS_RULE / DISPLAY_STANDARD / BUSINESS_CONTEXT）是前端本地夹具，**这恰恰是 LLM 生成最需要的"报告蓝图"，却没有进入服务端也没有接到 Definition**。

结论：配置化没有错，缺的是**第二份、更高一层的配置**——报告蓝图（Blueprint），由模型产出、服务端展开为 Definition。

### 2.2 通用卡片（规划②）

已成立的部分：组件清单是唯一注册表（`internal/report/template/manifests/*.json`，13 种），带数据合同（维度/度量上下限、角色白名单、可加性要求）、
optionSchema、移动策略；`insight` 有 14 种分析方法（`CURRENT_VALUE / PERIOD_COMPARISON / TREND / TOP_N / CONTRIBUTION / RANKING …`）；
Block 有 `ANALYSIS_CARD/KPI_GROUP/CHART/TABLE/CONTENT/FILTER` 六类，Zone 有 `HEADER/FILTER/INSIGHT/CONTENT/FOOTER`。

卡点：
1. **"通用卡片"目前落在展示层而不是语义层。** 用户规划里的"结论卡、对比卡、排名卡、表格卡"是**语义卡片**（回答什么问题）；
   现在能选的是"折线图、横向柱图、指标卡"（怎么画）。二者的映射知识（排名 → 横向柱 + TOP_N + RANKING 结论）现在散落在
   `answer.RecommendChart` 与 `instantiate.go` 里，模型只能直接挑组件。
2. **KPI 类卡片没有比较结构。** `metric-card` 合同是 1..3 个度量 + 0..1 维度，没有"本期 / 对比期 / 目标"槽位；
   同环比、达成率只能靠 insight 文字表达，无法在卡片上作为数字展示。这直接决定 AI 生成的月报"看起来不像月报"。
3. **卡片是原子的，缺"卡片组合"。** 月报里常见的"KPI 组（4 张并排）""左图右结论""上总下分"是重复出现的复合结构；
   `KPI_GROUP` 是 BlockType 但没有专门的生成规则与合同。
4. 结论卡（`insight-text`）**必须绑定度量**，且结论只能针对单卡证据；缺"报告摘要卡 / 章节导语卡"（跨卡片证据）。

### 2.3 视觉模板（规划③）

现状：`ThemeReference{themeId,version}` 存在于 Definition 并进入依赖索引（`compiler/index.go`），`platform.report_themes / report_theme_versions`
表也在（`migrations/000235`），但**没有种子行、没有 Go 读取器、没有前端消费者**；服务端在新建时写死 `theme_corporate_light@1.0.0`
（`http/handler.go:381`）。`report.css` 2300+ 行引用的是应用全局 `global.css :root` 的 token 外加大量字面量（`#0872d3`、`#26303f`…），
不是按报告/租户可切换的主题；`ComponentOptions.ColorPaletteRef` 在 6 个清单里声明、前端 `chart-option.ts` 从不读取，ECharts 用内置默认色。
另外 `ComponentOptions` 是一个封闭的扁平结构体（约 18 个字段全组件共用），新增任何视觉属性都要改 Go 结构而不是改清单。

卡点：视觉模板是**零实现**，且当前 CSS 写法（页面级字面量）无法在不重构的前提下切换主题。要做到"开发完成后配主题即换样式"，
主题必须是可发布的资产（token + 图表色板 + 卡片变体 + 密度），渲染器只消费 token。

### 2.4 拖拽布局（规划④）

现状：桌面画布被 `Canvas.validate` 冻结为 `1920 / 24 列 / 80 格宽 / 54 行高 / 12 间距 / 24 内边距`（`model.go:760-772`），移动端是 order/heightMode/slotMode 的投影；
拖拽/缩放/让位/章节排序全部是 Operation（`placement.ts` 在客户端先消解碰撞，服务端以 `REPORT_LAYOUT_COLLISION` 兜底）；
生成时 `Instantiate` 按 `desktopHint.w/h` 纵向堆叠（`x` 恒 0）。

卡点：
1. **坐标是唯一真相**，没有"布局意图"（这一节是 4 张并排 KPI；这张卡占 2/3 宽、右侧放结论；表格通栏）。
   模板复用、主题切换密度、AI 生成、移动投影都各自重复求解，且互相不一致。
2. AI 生成结果**一列到底**，用户拿到后仍要大量拖动，L2 的体验瓶颈主要在这里。
3. 桌面/移动双份布局手工维护，模型更不可能同时给出两份合理坐标。

### 2.5 卡片绑定数据集（规划⑤）

现状：`DataBinding{bindingMode: DATASET_FIELD|SEMANTIC_IR, dataContextId, dimensions[], measures[]}`；字段角色来自数据集 DSL；
`DATASET_FIELD` 汇总到绑定维度、不可加度量失败关闭；`SEMANTIC_IR` 只能由问数回填产生。

卡点：
1. **绑定单位是字段，不是指标。** 一个业务指标的口径（度量 + 聚合 + 时间合同 + 过滤 + 可加性）在语义层已有（Semantic Release），
   但编辑器和 AI 规划都只在"数据集字段"层工作，模型看到的是 `AllowedFieldNames`（一串字段名），没有指标定义、维度定义、业务口径说明、时间合同、数据画像。
   模型不知道"毛利率"怎么算、"报告期"是哪个月、"区域"有几个值。
2. **派生度量无处声明。** 同比/环比/占比/达成率/排名是报告最常见的数字，现在既不是绑定，也不是组件选项，只是 insight 方法。
   `SEMANTIC_IR` 绑定虽然完整受治理，却**不能在草稿上执行**（`target.go` `CodeDraftPreviewRequiresPublish`），
   而 AI 生成只会产出 `DATASET_FIELD`；两条绑定路径能力不对称。
3. **AI 生成只允许一个数据集**（`SelectDataContext` "Choose exactly one"），而真实报告横跨损益/应收/库存多张 ADS 表（`monthly-operating-template.json` 就需要三张）。
4. 生成前**不看数据**：模型只凭字段名规划，无法知道某个维度只有 1 个值、某个度量全空，导致空卡。

### 2.6 筛选器与共享维度（规划⑥）

现状：`GlobalFilter{type, fieldRef{dataContextId, field}, scope{REPORT|PAGE|SECTION|BLOCK|COMPONENT}, defaultValue}`；服务端解析取值；`Interaction.FieldMappings` 支持联动时的字段映射。

卡点：
1. **筛选器只在同一 DataContext 内生效。** `runtime/dataset_runner.go` 的 `datasetPredicates` 会跳过 `filter.DataContextID != dataContextID` 的过滤器；
   多数据集报告里，绑定在数据集 A 的"区域"筛选器不会过滤绑定数据集 B 的卡片。规划⑥"依赖维度可在其他卡片作为过滤字段"在多数据集下不成立。
2. **没有报告参数。** "报告期 = 2026-07""对比期 = 上月""口径 = 含税"这类参数既驱动查询也驱动结论文字，现在只能各自设筛选器默认值，结论文本无法引用。
3. 没有公共维度（Conformed Dimension）的声明与映射，AI 也无法判断哪些维度可以做全报告筛选。

## 3. 离"LLM 自行生成报告"还差什么

现有 L2 链路：意图 → 模型选 1 个数据集（`report-context-v1`）→ 模型出计划（`report-plan-v1`：章节 / 卡片 / 字段角色 / 组件 / 方法 / w,h）
→ 服务端确定性实例化（`Instantiate`）→ insight 区留空 → 用户逐卡 `derive` + `generate` 结论 → 发布。

| # | 缺口 | 为什么必须有 | 归属 |
|---|---|---|---|
| G1 | **报告上下文包（Context Pack）**：模型规划前拿到的不是字段名列表，而是指标目录（口径、聚合、可加性、时间合同）、维度目录（层级、基数、样例值）、数据画像（最新期、行数、空值率）、可选模板、报告类型规则 | 没有输入就没有判断；现在的空卡与"用错字段"多半源于此 | 服务端 |
| G2 | **报告蓝图（Blueprint）中间表示**：模型输出叙事结构（章节 → 分析问题 → 语义卡片 → 指标/维度/对比/方法/预期结论）+ 布局意图 + 报告参数 + 主题；服务端确定性展开成 Definition | 让模型只写它擅长的部分；蓝图可校验、可 diff、可复用为模板 | 契约 |
| G3 | **语义卡片库（Card Kind）**：KPI（含对比期/目标）、趋势、对比、排名、构成、明细、结论、摘要、导语；每种卡片有数据合同、默认组件与备选、默认分析方法、默认布局意图 | 模型说"排名卡"，服务端决定 bar-horizontal + TOP_N；卡片种类是模型与引擎之间稳定的词表 | 服务端注册表 |
| G4 | **派生度量与报告参数**：绑定层支持 `derived: {kind: PERIOD_COMPARISON|SHARE|ACHIEVEMENT|RANK, ...}`；Definition 支持 `parameters`（报告期等），筛选器/结论/标题都能引用 | 月报的数字大多是派生数字 | Schema + 引擎 |
| G5 | **多数据集 + 公共维度映射**：AI 生成可选多个 DataContext；`dimensionMappings` 声明"数据集 A.region ≡ 数据集 B.region_name"；筛选器按映射跨数据集生效 | 真实报告跨表 | Schema + 运行时 |
| G6 | **布局求解器**：从布局意图（行/列/权重/卡片种类默认尺寸/主题密度）确定性求解桌面与移动坐标 | 消除"一列到底"，同一意图在不同主题下自动重排 | 服务端 |
| G7 | **视觉主题资产**：token（色/字/距/圆角/阴影）+ 图表色板 + 卡片变体 + 密度，渲染器改为消费 token；主题为可发布资产 | 规划③零实现 | 服务端 + 前端 |
| G8 | **探索执行环（Explore → Refine）**：蓝图落地后先按草稿执行全部卡片（已有 `draft/execute`），把结果摘要（有无数据、行数、极值、显著性）回灌模型做一次精修：删空卡、换卡种、调 TopN、决定哪些卡值得写结论 | "先算后写"是分析报告的基本纪律；也是空卡率指标的来源 | 编排 |
| G9 | **批量结论与报告摘要**：生成链路自动对所有分析卡执行 `derive → generate → verify`；新增跨卡片证据的报告级摘要/章节导语（仍是标记写作 + 服务端代入） | L3 定义为"结论已生成"；现在是逐卡手动 | 编排 + insight |
| G10 | **AI 侧操作合同**：为改稿提供意图级、无条件关键字、内联的严格 Schema（如 `ADD_CARD/REPLACE_CARD/SET_PARAMETER/MOVE_SECTION`），服务端展开为现有 43 种 Operation | 解除 docs/12 §6 阻塞；对话式改稿依赖它 | 契约 |
| G11 | **生成质量评测与门禁**：结构合规、事实校验通过率、空卡率、布局重叠、人工评分；作为提示词/蓝图 Schema 变更的回归集 | 没有度量就没有迭代 | 评测 |
| G12 | **模板与经验回流**：把已发布报告反向抽取为蓝图模板；模板中心的分析思路模板服务端化，作为蓝图的输入约束 | 复用组织内既有分析框架，比 few-shot 更稳 | 资产 |

优先级：G1–G3 + G6 + G8 + G9 是 L3 的必要条件；G4/G5/G7 决定"像不像月报"；G10–G12 决定可迭代性。

## 4. 产品原则

1. **模型写蓝图，引擎写报告。** 模型输出的每一个对象都必须在服务端词表（卡片种类、指标、维度、方法、主题）之内并经校验；坐标、ID、SQL、数字永远由服务端产生。
2. **蓝图即模板。** 任何一份生成结果都能保存为蓝图模板；任何模板都能带参数再次生成。人手工搭出来的报告也能反抽为蓝图。
3. **同一份 Definition，同一条发布链。** 生成、改稿、手工编辑最终都落到 Report Definition 1.x 与受控 Operation；不引入第二套渲染器或第二套运行时。
4. **无模型可用时不降级为不可用。** 蓝图展开、布局求解、主题、派生度量、公共维度全部是确定性能力；模型缺席时只是没人写蓝图和结论。
5. **先算后写，写必可证。** 卡片先执行、后写结论；结论只写标记；未通过事实校验的结论不出现；报告摘要只能引用已通过的卡片结论与证据。
6. **人只审、不修坐标。** 生成结果的默认审阅动作是"改一句话 / 换一张卡 / 删一节"，而不是拖格子；对话改稿走意图级操作。

## 5. 概念模型（五层）

```
报告 Report
├─ 叙事结构 Narrative        章节 → 分析问题 → 卡片；导语/摘要/建议
├─ 语义卡片 Card             kind（KPI/TREND/COMPARE/RANK/COMPOSITION/DETAIL/INSIGHT/SUMMARY/TEXT）
│    ├─ 数据合同             指标（含派生）/ 维度 / 对比期 / 目标 / TopN / 数据集
│    ├─ 分析方法             来自 insight 注册表，卡片种类给默认
│    └─ 展示                 组件类型由推荐规则从合同求得，可覆盖
├─ 数据合同 Data             dataContexts + parameters + dimensionMappings + filters
├─ 布局意图 Layout Intent    row/columns/span/weight/order；求解器→ desktop/mobile 坐标
└─ 视觉主题 Theme            token/palette/variant/density；渲染器只消费 token
```

- **蓝图（Blueprint）** = 上面五层的"意图版"，模型可写、schema 严格、体量小；
- **定义（Definition）** = 展开后的"事实版"，即现有 Report Definition（升到 1.1：加 `cardKind`、`layoutIntent`、`parameters`、`dimensionMappings`、派生度量、主题实化）；
- 展开是确定性、幂等的：同一蓝图 + 同一上下文 → 同一 Definition（沿用 `deterministicIDFactory` 思路）。

### 5.1 语义卡片种类（首批）

| kind | 回答的问题 | 数据合同 | 默认组件 / 备选 | 默认方法 | 默认布局意图 |
|---|---|---|---|---|---|
| KPI | 关键指标本期是多少、变化多少 | 1..4 指标，可选对比期与目标 | metric-card（新增对比/目标显示） | CURRENT_VALUE, PERIOD_COMPARISON, TARGET_ACHIEVEMENT | 一行 2–4 张并排 |
| TREND | 随时间怎么变 | 1..3 指标 + 时间维 + 可选系列 | line-trend / area-stacked | TREND, ANOMALY_POINT, MAX_CHANGE | 2/3 宽 + 右侧结论 |
| COMPARE | 谁高谁低、和对比期差多少 | 1..2 指标 + 1 分类维 + 可选对比期 | bar-comparison | GROUP_DIFFERENCE, PERIOD_COMPARISON | 1/2 宽 |
| RANK | 前/后 N 是谁 | 1 指标 + 1 维 + TopN | bar-horizontal / data-table | TOP_N, RANKING | 1/2 宽 |
| COMPOSITION | 构成与占比 | 1 可加指标 + 1 维 | pie-donut / bar 堆叠 | SHARE_OF_TOTAL, CONTRIBUTION | 1/3 宽 |
| DETAIL | 明细 | n 字段，DWD/ODS 数据集 | data-table | DATA_COMPLETENESS | 通栏 |
| INSIGHT | 对某张卡的结论 | 引用同卡合同 | insight-text | 继承来源卡 | 附着在来源卡 INSIGHT 区 |
| SUMMARY | 报告 / 章节级摘要 | 引用多张卡的已验证证据 | insight-text（新 role） | 新：SUMMARY | 章节首/报告首通栏 |
| TEXT | 说明、方法、备注 | 无 | rich-text | 无 | 通栏 |

卡片种类是**词表**，注册在服务端（与组件清单同级），前端组件面板按 kind 分组展示，取代现在按 图表/表格/内容/控件 分组。

## 6. 用户旅程与功能

### 6.1 一句话生成（L3 主链）

1. **输入**：意图（自然语言）+ 可选：模板、数据集范围（默认当前领域全部已发布 ADS/DWS）、报告参数（报告期默认上一个完整周期）、主题。
2. **澄清（最多一轮）**：仅当上下文包判定不可决策（意图与任何指标不相关 / 报告期无数据 / 多个同名指标）时提出 ≤3 个选择题；否则跳过。
3. **蓝图预览**：以大纲形式展示章节 → 卡片（kind、指标、维度、对比、方法），用户可增删改（这是"改意图"，成本远低于改坐标）。默认可直接"生成"。
4. **生成**：展开 → 布局求解 → 草稿执行 → 精修（自动删空卡 / 换卡种）→ 批量结论 → 摘要。进度按章节展示；每步的裁决可见（哪些卡被删、为什么）。
5. **审阅**：进入编辑器，右侧"AI 生成报告"面板列出：结论校验状态、被删卡片、建议动作；顶部报告参数条。
6. **发布**：现有 publish-review / publish 链不变。

### 6.2 对话式改稿

- 输入自然语言 → 模型输出意图级操作（G10）→ 服务端展开为 Operation Bundle → 预览 diff → 用户应用（现有 `ai/preview` 位置）。
- 允许集：增删换卡（按 kind）、改参数、改章节顺序、改标题/结论、切主题；不允许：增删数据集（保留现有约束）。

### 6.3 视觉主题

- 主题中心：内置 2–3 套（企业蓝 / 高对比 / 打印友好），可复制修改并发布版本；报告可在编辑器与发布后切换（`THEME_UPDATE` 操作，重新求解布局密度）。
- 主题内容：色 token（页面/卡片/文本/边框/强调/语义色）、字号阶、间距密度、圆角/阴影、图表色板（分类/顺序/发散）、卡片变体（默认/无边框/强调）。
- 渲染器只消费 CSS 变量；导出（PDF/图片）沿用同一 token。

### 6.4 报告参数与公共维度

- 报告参数：`period`（必有，默认上期）、`comparePeriod`、业务参数；显示在运行页顶部；结论文本可通过 `{{param:period}}` 引用；定时任务按参数重跑（对接 L4）。
- 公共维度：数据集加入报告时自动按字段语义匹配候选映射，用户确认；确认后该维度可作为全报告筛选器并跨数据集生效。

### 6.5 结论与摘要

- 卡片结论：现有链路（标记写作 → 代入 → 校验），改为生成时批量执行；
- 章节导语 / 报告摘要：输入为该章节（或全报告）内已通过校验的卡片结论 + 证据摘要；输出仍是标记文本；服务端校验每个标记都指向已存在的证据；
- 建议（Action Items）：单独一段，标注为"模型建议、未经数据证明"，样式区分（主题提供 variant）。

### 6.6 模板

- 任意报告 → "另存为模板"：反抽蓝图（去实例化：字段 → 指标/维度引用，坐标 → 布局意图）；
- 模板中心服务端化，替换本地夹具；模板 = 蓝图 + 参数声明 + 适用数据集条件；
- 生成时模板作为蓝图的强约束（模型只能填空/裁剪，不能改结构）。

## 7. 界面要点

- **新建向导**新增"AI 成稿"页签：意图输入、模板选择、参数、主题；下方是蓝图预览大纲（可编辑），主按钮"生成报告"。
- **编辑器**：组件面板按 kind 分组；卡片配置面板首项改为"卡片种类"，其次指标（而非字段）、维度、对比期、TopN；展示类型退为"高级"。
- **生成面板**：生成日志（步骤 / 裁决）、结论状态列表、"重新生成本卡结论 / 本节"。
- **运行页**：顶部参数条 + 筛选栏；摘要卡在首屏。
- 视觉延续 docs/06 规则 15/18（蓝白灰、React 原生）。

## 8. 非目标与边界

- 不做自由布局（绝对像素）；不做第二套渲染器；不让模型直接产出 Definition 或 SQL；
- 不放松发布门禁、事实校验、权限裁剪、可加性约束；
- L4（定时重跑与推送）、跨报告对比、Word/PPT 排版导出不在本期。

## 9. 里程碑与验收

| 阶段 | 内容 | 验收 |
