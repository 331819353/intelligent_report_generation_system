## 可以提问的问题

### 直接指标

当前验证的 22 个生效指标包括：

- 运营：总订单数、已完成订单数、取消订单数量、毛收入、净收入、投诉数量、退款金额、在线时长
- 订单金额：商品总价、优惠金额、配送费、平台补贴金额、商家补贴金额、净支付金额
- 商品：SKU 实体数量、订单商品数量合计、订单商品折扣金额合计、订单商品行项目金额合计
- 实体与事件：用户实体数量、配送区域实体数量、骑手实体数量、配送事件记录数

示例：

- `请问净支付金额是多少？`
- `请问总订单数是多少？`
- `请问骑手实体数量是多少？`
- `请问配送事件记录数是多少？`

历史别名 `商品折扣`、`数量`、`行项目金额` 会解析到当前发布指标版本，而不是继续执行已废弃指标。

### 时间分析

对 `AGG_MERCHANT_DAILY_OPS` 的总订单数、已完成订单数、毛收入、净收入，可以使用明确日期过滤。

- `2026-06-10的净收入是多少？`
- `2026-06-30的总订单数是多少？`

日期会转换成左闭右开的时间范围。例如 `2026-06-10` 对应 `[2026-06-10, 2026-06-11)`，避免日期边界重叠。

## 本轮通用改进

1. 指标解析优先使用当前发布指标、治理别名和精确锚定词元，降低相似指标误选与不必要的向量召回。
2. 明确年月日采用确定性解析，并修复两位数月份、日期被一位数分支截断的边界问题。
3. 维度成员在“当前指标可兼容维度”内执行完整短语匹配，统一支持空格、下划线和标点成员；选择最长治理短语并保留歧义拒绝机制，没有为 BANK_CARD 或某个具体类目增加特判。
4. 无成员筛选的分组维度也进入不可变查询条件、意图和 Semantic IR，使排行、分布的语义契约与实际执行列一致。
5. 评测工具从接口结果反向验证版本、血缘、哈希和安全属性，不用模型自评作为准确率依据。

## 证据边界与下一门槛

本报告属于当前快照上的开发环境 E2E 验证。它已经证明本次目录化问题域超过 95% 准确率门槛，但还不是正式封版门禁。实施方案中的正式封版仍应具备：

- 至少 2,000 个经过独立人工复核并封存的问题；
- 覆盖更多自然语言改写、组合筛选、权限拒绝、歧义拒绝、空结果和故障注入；
- 固化数据快照、题集版本、期望结果哈希和执行环境；
- 将准确率、Wilson 下界、性能与安全套件接入 CI/CD 发布阻断。

因此，当前可严谨表述为“302 题目录化开发验证 100%，95% Wilson 下界 98.74%”，而不是“所有未知问题永久 100%”。
