# 智能分析决策平台容量基线与生产 POC 运行手册

> 范围说明：本文件同时定义平台混合负载模型和 AskData 专项压测。它给出可重复的软件验收合同，
> 但不把开发机或单节点 Compose 结果冒充目标环境容量结论。`OPS-007` 只有在目标拓扑完成混合负载、
> 故障注入、恢复收据和业务 Owner 签署后才能整体关闭。

本文件是 `OBS-003` / `OPS-004` / `OPS-007` 的可重复执行入口，不是生产容量结论。生产副本数、
partition、连接池和并发预算只有在 `HUMAN-013` 提供目标规模、SLO 与目标环境后，使用该环境的
报告才能签署；开发机或单节点 Compose 报告不得用于生产推断。

## 平台混合负载合同

压测配置必须显式给出下列变量；缺少任一变量时报告状态固定为 `POC_NOT_SIGNED`，运行器不得以默认值
生成生产建议。

| 业务面 | 必填负载变量 | 主要资源与排队点 | 必须记录的结果 |
|---|---|---|---|
| 登录与领域选择 | `loginRps`、`refreshRps`、活跃 session、每用户领域数 | API CPU、密码校验、`auth_sessions`、RBAC/领域查询连接 | P50/P95/P99、失败率、锁等待、领域切换后旧 scope 拒绝率 |
| AskData | 并发问题数、Fast/Complex 比例、候选数、图跳数、结果行上限 | API/Worker、LLM Provider、PostgreSQL、pgvector、Nebula、数仓池 | 端到端延迟、各阶段排队、Recall@K、降级/澄清/超时率 |
| 报告运行 | 并发查看者、每报告组件数、唯一 Query Plan 数、缓存命中率 | runtime planner、只读数仓池、结果缓存、组件聚合 | 首屏/全量延迟、去重率、单组件失败率、查看者隔离命中 |
| 导出 | 每分钟提交数、格式分布、结果体积分布、并发 worker 数 | 导出队列、数仓池、CPU/内存、对象存储吞吐 | 队列等待、生成时长、峰值内存、对象大小、过期/失败率 |
| 报告调度与站内分发 | 活跃计划数、同分钟到期数、订阅人数、补跑比例 | schedule claim、delivery claim、报告运行、通知写入 | 调度漂移、`MISSED`、重试、自动暂停、重复投递数 |
| 统一待办与通知 | 每用户未结项数、列表/详情 RPS、已读写入 RPS | 跨模块受权聚合、keyset 查询、receipt/notification 索引 | 列表延迟、分类总数一致性、无权项过滤、去重率 |
| 决策与行动复盘 | 新建/审批 RPS、活跃行动数、同分钟截止/复盘数 | decision 状态机、due worker、Evidence 校验、当前策略重放 | 写冲突率、due lag、通知去重、复盘执行/无权/漂移比例 |

混合报告必须保存各业务面的权重、升压曲线、稳态时长和唯一 seed。只跑单一接口、只跑 AskData 或把
视觉页面渲染耗时混入后端服务延迟的报告，均不得作为平台容量签署材料。

## 资源预算与准入门禁

目标环境配置必须填写 `apiConcurrencyBudget`、各 Worker 并发、控制库/数仓连接池、Provider 并发、
对象存储吞吐和队列 lag 预算。软件层按以下原则失败关闭：

- API、Worker、连接测试角色使用独立连接预算；AskData、报告 runtime、导出、调度和决策 due worker
  不得共用一个无上限池，也不得通过提高全局池上限掩盖排队。
- 稳态验收必须同时满足目标 SLO，并保持 CPU、内存、数据库连接和对象存储吞吐在目标环境预留水位内；
  水位数值由 `HUMAN-013`/运维签署，未填写时只输出观测值，不输出“可承载”结论。
- 任何业务面触发 admission limit 时必须返回稳定的限流/排队/降级状态；不得静默丢任务或越过权限、
  Evidence、不可加性和发布版本校验换取吞吐。
- 调度、导出和 due worker 的容量按“最老可处理项 lag”而非仅按吞吐验收；稳态结束仍增长的 backlog
  视为失败。

## RTO、RPO 与降级边界

本仓库定义恢复计时点和数据边界，具体时长由目标环境签署，不在代码中编造：

| 数据/能力 | RPO 计量点 | RTO 计量终点 | 恢复前允许的降级 | 不允许的降级 |
|---|---|---|---|---|
| 身份、租户、领域、权限 | 控制库最后可验证 WAL/备份点 | 登录成功且旧/错领域 scope 继续拒绝 | 只读维护页 | 绕过登录或领域权限 |
| AskData/语义事实 | 同一控制库恢复点 + 对象存储校验点 | 固定 Release 可问，投影 hash 一致 | 图不可用时走既定有界 PostgreSQL 降级 | 使用未认证语义、旧权限缓存或隐藏降级 |
| 报告主对象/版本/制品 | 控制库恢复点 + 制品对象 hash | 已发布版本可按当前查看者运行 | 暂停 AI 编辑、导出与分享创建 | 用草稿/缺制品版本代替已发布版本 |
| 导出/调度/分发 | 控制库队列事实恢复点 | 过期 lease 已回收，积压项得到确定终态 | 暂停新任务、保留查询/下载已验证制品 | 重复投递、附带数据或扩大订阅权限 |
| 待办/通知 | 来源业务事实恢复点 | 分类计数与来源状态一致 | 临时隐藏不可确认的聚合项 | 从复制摘要执行动作或显示已处理项 |
| 决策/行动/复盘 | decision 事实与 Evidence 引用所在恢复点 | 事件链、行动截止和复盘引用闭包通过 | 暂停新审批/复盘执行 | 改写历史 Evidence/actor 或自动确认复盘 |

`RTO_*` 从事故声明/恢复演练开始计时，到对应“计量终点”全部通过为止；`RPO_*` 以最后成功恢复且闭包
校验通过的事实时间为准。报告必须记录实际值和已批准目标，任一为空都保持 `POC_NOT_SIGNED`。

## 故障注入矩阵

目标拓扑至少各执行一次：API 实例丢失、通用 Worker 重启、控制库主节点切换、数仓超时/连接池耗尽、
对象存储短暂不可用、Nebula 不可用、Provider 限流，以及恢复点跨越报告调度窗口/行动截止时间。每次
注入都必须证明其他业务面符合上表降级边界，并记录 backlog、重试、恢复后重复数和权限负向结果。

## 首期规模假设与升级检查点

| 维度 | 首期假设 | 触发复核 |
|---|---:|---:|
| 租户 | ≤ 20 | > 50：检索按租户分区 |
| 业务域 | 首期 1，12 个月内 ≤ 5 | > 10：评估按域拆分图 Space |
| 检索文档 | ≤ 200,000 | > 2,000,000：评估独立向量服务 |
| FULL 成员/域 | ≤ 50,000 | > 200,000：强制转 ON_DEMAND |
| ON_DEMAND 成员/域 | ≤ 5,000,000 | > 50,000,000：Lookup 表分区 |
| 日问数运行 | 2,000～10,000 | > 50,000：复核缓存层 |
| 峰值并发问数 | 20～50 | > 200：水平扩容并重算连接池 |
| 已发布报告 | ≤ 2,000 | > 20,000：评估制品 CDN |
| 图顶点/边 | ≤ 100,000 / 500,000 | > 10,000,000 边：多副本容量 POC |

这些值只是架构复核阈值。`internal/askdata/observability/capacity.go` 会在报告越过阈值时生成稳定
告警，不会自动修改生产拓扑或扩大容量声明。

## 运行前门禁

1. 使用与生产同版本、同副本、同 partition、同连接池配置的隔离环境；记录节点 CPU、内存、磁盘、
   网络、PostgreSQL/Nebula/LLM Provider 版本与配置标签。
2. 准备专用租户、业务域、认证问法、Complex 问法、仓库超时、三跳图、向量召回和六计划 KPI Bundle
   夹具。不得把密封集问题正文写入配置或报告。
3. 通过环境变量 `ASKDATA_LOADTEST_BEARER_TOKEN` 注入短期访问令牌；配置文件不得包含
   Authorization、Cookie 或令牌。每个 POST 的唯一 `Idempotency-Key` 由运行器根据 seed、场景和请求
   序号生成。
4. `VECTOR_RECALL`、`GRAPH_3_HOPS`、`LLM_DEGRADATION` 使用部署侧受控容量适配端点；端点只返回
   状态码和 `X-AskData-*` 聚合头，不返回问题正文、查询参数或结果行。

## 执行

先复制并替换示例中的业务域、问法和受控适配端点：

```sh
cp scripts/loadtest/config.example.json /secure/askdata-capacity.json
ASKDATA_LOADTEST_BEARER_TOKEN='short-lived-token' \
  go run ./scripts/loadtest \
  -config /secure/askdata-capacity.json \
  -output /secure/askdata-capacity-report.json
```

同一配置和 seed 可重复运行；报告只保存环境标签、规模、计数、分位数、Recall@K 和失败码 hash，
不保存响应正文。必须覆盖：Fast Path、Complex Loop、仓库连接池/statement timeout、pgvector
Recall@K、Nebula 三跳、Provider 限流/熔断和 KPI Bundle 并发计划。

上述命令是 AskData 子场景入口。平台签署还必须用同一个 `environment.configHash` 运行登录/领域、报告
runtime/导出、调度/分发、工作箱和决策 due 场景；若目标环境尚未提供对应混合运行器，可使用外部受控
压测器，但请求集合、seed、幂等键规则、聚合字段和脱敏要求必须随报告归档。

## 容量签署清单

生产建议必须同时附上：

- 原始 JSON 报告及其 `environment.configHash`；
- API/Worker/PostgreSQL/Nebula/向量索引的 CPU、峰值内存和存储增量；
- 数据库与数仓连接池占用、排队和 statement timeout 统计；
- 当前及建议副本数、partition、连接池、每租户/每域并发预算；
- 所有 `EvaluateCapacityAlerts` 告警的处置或风险接受记录；
- 两次同配置复跑的 P50/P95/P99、成功率和 Recall@K 对比。
- 各子系统实际 RTO/RPO、恢复收据、故障注入时间线、积压清零证据和重复投递计数；
- 业务 Owner、平台运维和安全责任人的签署，或逐项风险接受记录。

缺少任一项，或报告来自开发单节点，结论状态必须保持 `POC_NOT_SIGNED`，不得写入生产容量基线。
